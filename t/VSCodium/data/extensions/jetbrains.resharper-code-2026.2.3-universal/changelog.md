| 2026.2.1 | **[NEW]**: [VSRS-1260](https://youtrack.jetbrains.com/issue/VSRS-1260) This release introduces several **Entity Framework inspections**, each with its own quick-fix: <br> - *Possible multiple queries to the database for related entities (N+1 problem)*: finds cases where looping over query results causes extra database calls for related entities. The quick-fix adds `Include()` or `ThenInclude()` to the initial query so all data is fetched at once. <br> - *Query can return incomplete data for related entities*: flags queries that access related entities without eager loading, which can lead to incomplete data. The quick-fix adds the missing `Include()` or `ThenInclude()` calls. <br> - *Possible performance issues caused by unlimited string length*: highlights entity string properties without a length limit, which map to `nvarchar(max)` columns and may hurt database performance. The quick-fix adds a `[StringLength]` attribute. You can also use `[MaxLength]` or the `HasMaxLength()` builder method. <br> - *Function is not convertible to SQL and must not be called in the database context*: warns when a query calls a method that cannot be translated to SQL and would cause a runtime error. <br> - *Database function must not be called in non-database context*: warns when database-only functions, such as those from `EF.Functions`, are called outside a query. <br><br> [See the full list of changes](https://youtrack.jetbrains.com/issues/VSRS?q=Available%20In:%202026.2.1%20).

The registry requires that a published binary of an extension cannot exceed 256 MB in size. Unfortunately, the `.vsix` file for Windows ARM64 was 275 MB, which is above that limit. While other platform-specific binaries were slightly below the limit, we anticipate that they will also soon exceed the size restriction.<br><br>To address this issue, we decided to redesign the extension's architecture and create a smaller core extension that downloads the larger components (including the ReSharper language server and .NET runtime) separately from the JetBrains download server upon the first start of the extension.<br><br>Unfortunately, there are a couple of downsides of this architectural change.<br>- The initial startup of the newly updated extension will take longer than before due to the need to download and unzip the larger components. However, this impact is minimal, and subsequent startups will not experience any additional delays.<br>- You will need an active internet connection and unrestricted access to the https://download.jetbrains.com/ server when opening the first .NET solution with the updated ReSharper extension. Once the download is complete, the extension will be fully functional without the need for an internet connection.<br>If you do not meet these requirements for any reason, the ReSharper extension will notify you and provide a link to download an OS-specific VSIX file, which contains all the necessary components for offline installation.<br><br>If you have any problems, comments, or questions regarding this change, please reach out to us on our [public tracker](https://youtrack.jetbrains.com/issues/VSRS). <br><br> **[NEW]**: [VSRS-647](https://youtrack.jetbrains.com/issue/VSRS-647) We introduced tons of typing assists (most of all from our legendary ReSharper for Visual Studio), including, but not limited to, correcting common language-specific typos when typing `;`, expanding `///` to an XML documentation comment, or auto-closing tags in Razor. **ACTION REQUIRED**: Make sure to enable the `Editor: Format On Type` option in your VS Code settings.
